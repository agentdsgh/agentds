# Предложения по доработке и исправлению

Список идей и известных слабых мест проекта agentds (agent_freedeepseek.py). Разделы упорядочены по приоритету.

## Критично

1. **Вынести `GITHUB_OWNER` / `GITHUB_REPO` в CLI-аргументы или переменные окружения.** Сейчас они жёстко зашиты в начале файла — проект работает только с одним репозиторием без правки кода. Нужен `argparse`: `--owner`, `--repo`, `--base`, `--issues`, `--limit`, `--dry-run`.
2. **Идемпотентность повторных запусков.** `_run_queue` пропускает issue со статусом не `error`, но если ветка осталась в промежуточном состоянии (push прошёл, PR упал), повторный прогон не докоммитит. Нужен «recovery»-режим: переиспользовать существующую ветку, допуш и доп.PR.
3. **Контроль размера контекста.** `TOOL_OUTPUT_LIMIT=12000` × `STEPS_PER_ROUND=6` × `MAX_ROUNDS=3` может дать 216k символов в истории — при 64k-контексте это `ContextExceeded`. Стоит суммировать/обрезать старые tool-результаты в `messages` перед отправкой.
4. **Точная оценка prompt_tokens.** `_estimate_prompt_tokens` использует chars//4 — для русского текста и BPE DeepSeek занижает в 1.5–2 раза. Лучше брать usage из прокси, если он начнёт отдаваться, или использовать токенизатор DeepSeek локально.

## Важно

5. **Единый хелпер Retry-After для GitHub и LLM.** Сейчас `_gh_retry_after` (GitHub) и `_retry_after` (LLM) живут отдельно. Стоит объединить в `_respect_retry_after(resp, attempt)`, чтобы не разъезжались.
6. **Мёртвая проверка `GH_PUSH["ok"]` в `gh_open_pr`.** После правки `_push_failed` (issue #2) флаг больше не выключается навсегда — проверка в `gh_open_pr` стала мёртвым путём. Решить: вернуть TTL-отключение или убрать проверку.
7. **Мёртвый код в `llm_stream`.** `max_retries = MAX_RETRIES_429 if False else max(...)` — упростить до `max(MAX_RETRIES_429, MAX_RETRIES_5XX)`.
8. **`clone_repo`: `r.stderr.replace(GITHUB_TOKEN or "\0", "***")`** — при `GITHUB_TOKEN=None` заменяется нулевой байт, а не секрет. Исправить на условие `if GITHUB_TOKEN: r.stderr.replace(...)`.
9. **`judge_result` при исключении возвращает `(None, note)`** — в отчёте выглядит как «нет вердикта», хотя судья упал. Возвращать `("ERROR", note)`.
10. **`write_file` проверяет только .py и .json.** Добавить `.yaml/.yml/.toml` валидацию, иначе можно записать битый конфиг.
11. **`codespace_exec` вызывает `git("add","-A","-N")` без try.** При сбое git весь вызов падает неинформативно. Оборачивать в `try` и возвращать `ERROR: ...`.

## Улучшения

12. **Дедупликация issues по body, а не только по title.** `find_duplicate` сравнивает Jaccard токенов title (0.6). Добавить body-токены или эмбеддинги для лучшей защиты.
13. **Параллельная обработка issues.** Очередь последовательная: один issue — один долгий прогон. Можно пускать N issue параллельно (с общим пулом троттлинга LLM и GitHub).
14. **Расширяемый список инструментов.** `make_tools` жёстко перечисляет функции. Плагинная регистрация (`@tool` декоратор) упростит добавление `run_tests`, `git_blame`, `gh_actions` и т.п.
15. **Сохранение/восстановление сессии.** Сейчас `new_sess` живёт только в памяти. При падении прогона теряются `commands`, `reports`, `created_issues`. Сохранять в `agent_out/sessions/issue-N.json`.
16. **Метрики качества.** Собрать статистику: сколько issue решено с первого раза, среднее число раундов, сколько токенов уходит, сколько раз сработал судья «НЕТ/ЧАСТИЧНО». Полезно для настройки `STEPS_PER_ROUND` / `MAX_ROUNDS`.
17. **Тесты.** Нет ни одного автотеста. Добавить `pytest`: юнит-тесты на `_safe`, `parse_text_call`, `coerce_args`, `_gh_retry_after`, `issue_status`; интеграционный — на фейковом GitHub API (`responses` / `vcr.py`).
18. **Docker/devcontainer.** Добавить `.devcontainer/` и `Dockerfile` с прокси FreeDeepseekAPI, чтобы `run_in_codespace` и локальный запуск работали из коробки.
19. **Кросс-платформенность.** `run_command` использует `os.killpg` — работает на Linux/macOS; на Windows нужен `CREATE_NEW_PROCESS_GROUP` и `taskkill`.
20. **Секреты в логах.** `_scrub` вычищает GITHUB_TOKEN, но не `FREEDEEPSEEK_API_KEY`, `GH_TOKEN` и токены из env. Расширить список.
21. **Кэш GitHub API.** `fetch_issues` + `load_known_issues` + `issue_text` дергают API на каждом прогоне. Кэшировать в `agent_out/cache/` с TTL 5–10 минут.

## Документация

22. **Примеры использования.** Добавить `examples/` со сценариями: «только dry-run», «только issues с priority:p0», «только чтение без push», «работа в Codespaces».
23. **Схема протокола инструментов.** В docs/USAGE.md есть пример, но нет полной грамматики (`@@CALL`, `@@ARG`, `@@END`, `_TRAILING_NEWLINE_ARGS`). Хорошо бы формализовать и покрыть тестами.
